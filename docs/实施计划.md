# 民宿在线预约管理系统 — 实施步骤计划（Phases）

技术栈（严格遵循基本设计书）：前端 Vue3，后端 Java + Spring Boot，数据库 MySQL，接口返回 JSON。
工程结构：`backend/`（Spring Boot：controller/service/mapper/entity/dto）+ `frontend/user/`（用户端 Vue3）+ `frontend/admin/`（管理端 Vue3）。

---

## Phase 0 — 环境与工程骨架（当前已落地）

**目标**：本机可跑通"数据库 → 后端 → 两个前端"的空转链路。

- [x] 逐张审阅 32 张画面 + PDF，输出《审阅纪要》（docs/审阅纪要.md）
- [x] MySQL Schema：25 张表 + 种子数据（backend/sql/schema.sql），统一状态枚举与单号规则
- [x] docker-compose.yml：一键启动 MySQL 8（自动执行 schema.sql）
- [x] Spring Boot 3.3 骨架：pom.xml、application.yml、统一 Result/PageResult/全局异常、JWT 双端认证（member/admin 拦截器）、CORS、MyBatis-Plus 分页、初始管理员 DataInitializer
- [x] 全模块 entity/mapper/service/controller 骨架与基础 CRUD
- [x] 用户端/管理端 Vue3+Vite 工程：路由铺齐 32 个画面、axios 封装、Pinia、Element Plus、布局组件
- [x] 全容器化：后端多阶段 Docker 构建（镜像内 Maven+JDK17 编译、JRE 运行），本机无需安装 JDK/Maven
- [x] 端口防冲突排查并固定：MySQL 13306、后端 8090、用户端 25173、管理端 25174（本机 8080/5173/3306 等已被其他项目占用）
- [ ] `docker compose up -d --build` 起库+后端；两个前端 `npm install && npm run dev`

**验收**：管理端能用 admin/admin123 登录进入看板空页；用户端首页能拉到种子房间数据。

## Phase 1 — 认证与基础数据（约 1 周）

**目标**：双端登录注册闭环 + 后台基础字典维护可用。

- 图形验证码、注册（唯一性校验）、双端登录/登出、JWT 过期处理、修改密码/资料（脱敏返回）
- 后台：会员类型、会员、房间类型、周边设施、轮播图、系统参数 六个标准 CRUD 页联调
- 文件上传（房间图/头像）与 /files 静态访问
- 操作日志记录接入管理端写操作

**验收**：画面 用户02/03/12、admin 01/03/04/05/06/09、18(轮播图/参数) 与后端联调通过。

## Phase 2 — 房间与预约支付主流程（约 1.5 周，核心）

**目标**：用户从"搜房 → 看详情 → 下单 → 支付 → 看订单"全链路走通。

- 房间管理（多图上传、上架/下架/维修中）+ 用户端房间列表（多条件+日期可用性过滤）+ 详情页
- 预约下单：日期区间占用校验（防超订，房间+日期唯一性并发控制）、后端重算金额（会员折扣）
- 支付：先做模拟支付通道（直接成功，写 payment 流水），支付结果页；真实微信/支付宝后续接入预留 PayChannel 接口
- 我的预定记录：状态 Tab、去支付、取消订单（已支付取消 → 生成退款申请）
- 后台预定记录管理：确认预约、取消、退款处理、预定详情页、管理员备注

**验收**：画面 用户01/04/05/06/07/08/13、admin 10/11 全联调；并发下同房同日期不可重复成单。

## Phase 3 — 入住、评价、投诉、公告（约 1 周）

**目标**：住中/住后业务闭环。

- 办理入住（订单 → 入住记录）、办理退房（联动订单完成）、入住记录管理、我的入住记录
- 评价：去评价（半星评分，一单一评）→ 后台审核（通过/不通过）/回复/删除 → 房间详情展示已审核评价与均分
- 投诉反馈：用户提交/查看 → 后台回复、标记已处理
- 公告：后台增删改 + 发布/下架 → 用户端列表/详情

**验收**：画面 用户09/10/16 + 个人中心各记录页、admin 12/14/15/16 联调通过。

## Phase 4 — 在线客服与数据看板（约 1 周）

**目标**：实时互动与运营驾驶舱。

- 客服：先以 REST 轮询骨架联调（已铺），再升级 WebSocket（Spring WebSocket/STOMP）：会话分配、未读数、快捷回复、结束会话；图片消息
- 数据看板：8 统计卡（含较昨日环比）、收入/预约趋势（近7天/30天/12月）、热门房间 TOP3、最新预订
- 收入管理：5 统计卡、趋势图、支付方式占比环形图、明细查询、Excel 导出（EasyExcel）
- 入住记录 Excel 导出

**验收**：画面 用户11、admin 02/13/17 联调；两端消息 3 秒内互达（WebSocket 后 <1s）。

## Phase 5 — 系统管理与权限（约 0.5 周）

- 菜单管理（树形）、角色权限（角色-菜单绑定，登录后按角色渲染侧边栏）、管理员账号管理、日志查询/清空
- 管理端接口按角色鉴权（拦截器补角色校验）

**验收**：admin 18 全部六个子模块可用；客服角色登录只见客服相关菜单。

## Phase 6 — 测试、加固与部署上线（约 1 周）

- 后端：核心 Service 单测（下单/取消/退款状态机、日期占用）、接口冒烟脚本
- 安全加固：密码策略、验证码防刷限流、SQL 注入/越权复查（订单归属校验）、上传类型白名单
- 前端：构建产物 Nginx 托管（/api 反代后端），或后端 static 托管两个前端产物
- 生产部署：MySQL 备份策略、日志滚动、systemd/docker 守护、HTTPS
- 资料交付：接口文档（springdoc-openapi 自动生成 /swagger-ui）、部署手册

**验收**：全画面回归通过，生产环境可用。

## 升级维护约定

- 状态枚举、单号规则以《审阅纪要》第 4 节裁定为准，禁止各端自定义
- 新增接口一律 `Result<T>` JSON 包装、分页统一 `PageResult`
- 涉及金额的计算只信后端；前端展示值仅供参考
- 真实支付、短信验证码、微信小程序渠道为预留扩展点（PayChannel / SmsSender 接口）
