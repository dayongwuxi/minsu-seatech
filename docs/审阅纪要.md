# 民宿在线预约管理系统 — 设计资料审阅纪要

> 审阅范围：`docs/design-mockups/` 用户端 14 张画面 + 管理端 18 张画面（逐张审阅）+ 《民宿在线预约管理系统基本设计》PDF 19 页（逐页精读）。
> 审阅日期：2026-07-07

## 1. 技术栈要求（基本设计书 P19 明确）

- 前端页面：**Vue3**
- 后端接口：**Java + Spring Boot**
- 数据库：**MySQL**
- 接口返回 **JSON**，Vue3 调用接口显示数据
- 参考工程结构：frontend（Vue3 页面）+ backend（controller 接口层 / service 业务层 / mapper 数据访问层 / entity 实体类 / dto 请求返回对象）

## 4. 设计稿不一致点与裁定（升级维护时注意）

| 问题 | 设计稿现象 | 裁定 |
|------|-----------|------|
| 订单号前缀 | DO2024… / DD2024… / D02024… 混用 | 统一 `DD + yyyyMMdd + 4位流水`；其余单号同规则（M/RM/RT/CR/R/FB/GG/SR/S 前缀） |
| 会员类型 | 04图：普通/VIP/长住；05图：普通/银卡/金卡/钻石 | 以 04 会员类型管理画面为准（类型可自行维护，不写死） |
| 房间类型 | 08图出现"海景房"，不在 06 图 6 种类型内 | 类型为可维护字典，种子数据用 06 图的 6 种 |
| 房间状态 | 列表：可预订/维修中/已满房；表单：正常/维护中 | 统一 0可预订 1维修中 2已满房 |
| 支付状态 | 待支付/已支付/待确认/已退款 混用 | booking.pay_status：0待支付 1已支付 2已退款 |
| 预约状态 | 用户端 4 态 vs 管理端 5 态 | booking_status：0待确认 1已确认 2已入住 3已完成 4已取消；用户端"已支付"由 pay_status 表达 |
| 06 图标题 | 图内标题误写"房间详情画面" | 实为预约表单页 |
| 金额计算 | 前端自动计算天数×单价 | 后端必须重算（含会员折扣），防篡改 |

## 5. 超出 PDF 的画面细节（已纳入模型，实现按阶段推进）

- 首页导航出现"景点游玩/美食信息/住宿套餐"→ 归入周边设施 type 字典即可覆盖
- 会员权益含积分（评价/权益说明提及）→ 骨架暂不建积分表，升级预留
- 客服会话含来源渠道（微信小程序）、会话时长、结束并评价 → cs_session 已含字段
- 数据看板/收入统计所有指标含"较昨日/上月"环比 → 接口需同时返回本期与上期
