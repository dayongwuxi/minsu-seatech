# 支付 / 促销 / 退款 域设计（Stripe 聚合支付）

> 参考 Airbnb 等民宿站的价格明细与退款模式。2026-07-08 设计定稿，作为前后端三方实现契约。

## 1. 支付架构

- 聚合层：**Stripe PaymentIntents**。一个 PayChannel 抽象：`MockPayChannel`（无密钥时降级，开发/演示用）+ `StripePayChannel`。
- 支持方式（配置驱动，`STRIPE_PAYMENT_METHODS` 逗号分隔）：`card`(信用卡) / `wechat_pay`(微信) / `alipay`(支付宝) / `paypay`(PayPay, 仅日本 Stripe 账户) / `paypal`(仅欧洲/英国 Stripe 账户)。UI 渲染以 `GET /api/payments/config` 返回为准。
- 货币：`PAYMENT_CURRENCY`（站点结算货币，默认 cny；历史名 `STRIPE_CURRENCY` 兜底兼容，2026-07-24 更名，见 LinkTrustPay接入设计）。金额换算注意零小数货币（jpy 不 ×100，cny/usd ×100）。
- 环境变量（compose 注入，缺省即 Mock 模式）：`STRIPE_SECRET_KEY`、`STRIPE_PUBLISHABLE_KEY`、`STRIPE_WEBHOOK_SECRET`、`PAYMENT_CURRENCY`、`STRIPE_PAYMENT_METHODS`。
- Webhook：`POST /api/payments/stripe/webhook`（Stripe-Signature 验签；放行免登录）。公网地址 `https://seabnb.axionintell.com/api/payments/stripe/webhook`。
- 兜底：支付结果页轮询 `GET /api/payments/result?orderNo=`，服务端在 webhook 未达时主动查询 PaymentIntent 状态同步（双保险）。

### 支付流程
1. 下单（服务端重算价格）→ booking(pay_status=0)
2. 前端 `GET /api/payments/config` → stripeEnabled? 
   - 是：`POST /api/payments/stripe/intent {orderNo}` → clientSecret → **Stripe Payment Element** 渲染可用支付方式 → confirmPayment(return_url=/pay-result/{orderNo})
   - 否：走原模拟支付 `POST /api/payments`
3. webhook `payment_intent.succeeded` → payment.pay_status=1、booking.pay_status=1；`payment_intent.payment_failed` → payment 记失败

## 2. 促销/折扣模型（Airbnb 式价格明细）

价格计算唯一入口：后端 `PriceService.quote()`。前端 BookingForm 调 `POST /api/bookings/quote` 实时展示明细；下单时服务端以同一逻辑重算，防篡改。

叠加顺序（在房费小计上依次计算，各优惠基于原始房费小计，不复利）：
```
房费小计 = 单价 × 晚数
- 促销优惠 promo_discount   （promotion 规则，自动匹配或优惠码触发，取优惠额最大的一条）
- 会员折扣 member_discount  （member_type.discount，对扣除促销后的余额计算）
= 订单总额 total_amount（≥0.01）
```

promotion 规则类型（type）：
| type | 含义 | 关键字段 |
|---|---|---|
| 1 百分比折扣 | 如 8 折 | discount_rate=0.80 |
| 2 满减 | 满 threshold_amount 减 discount_amount | threshold_amount, discount_amount |
| 3 长住折扣 | 连住 ≥min_nights 晚打 discount_rate | min_nights, discount_rate |
| 4 早鸟折扣 | 提前 ≥advance_days 天预订打 discount_rate | advance_days, discount_rate |

- `room_id` NULL=全场适用；`coupon_code` NULL=自动应用，非 NULL=需输入优惠码
- 有效期 start_date~end_date；usage_limit/used_count 限量（下单成功 +1）；status 启停
- `GET /api/promotions/active?roomId=` 供房间详情展示促销标签

## 3. 退款状态机

```
用户(我的预定 申请退款/已支付取消) → refund_record(status=0申请中)
→ 管理端预定管理[退款处理] 同意:
     Stripe单: 调 Stripe Refund API → status=1已同意(退款中) → webhook refund 成功 → status=3已退款
     Mock单:   直接 status=3已退款
   拒绝: status=2已拒绝
status=3 时联动: payment.pay_status=3已退款、booking.pay_status=2已退款;
  若未入住取消场景 booking_status=4已取消, 已完成订单退款则 booking_status 保持3
```
管理端新增 `GET /api/admin/refunds` 分页（申请列表集中处理）+ `PUT /api/admin/refunds/{id}/approve|reject`。

## 5. API 契约增量

用户端：
- `POST /api/bookings/quote` {roomId,checkinDate,checkoutDate,promoCode?} → {nights,unitPrice,roomFee,promoDiscount,promoName,memberDiscount,totalAmount,currency}（需登录；promoCode 无效时 code=400 提示）
- `POST /api/bookings` 请求体增加 promoCode（服务端重算并落 breakdown 列）
- `GET /api/payments/config` → {stripeEnabled,publishableKey,methods[],currency}（免登录）
- `POST /api/payments/stripe/intent` {orderNo} → {clientSecret,paymentIntentId,amount,currency}
- `POST /api/payments/stripe/webhook`（免登录，验签）
- `GET /api/promotions/active?roomId=`（免登录）
- `POST /api/bookings/{orderNo}/refund` {reason}（已有，语义不变）

管理端：
- `GET/POST/PUT/DELETE /api/admin/promotions` + `PUT /{id}/status`（分页查询: name/type/status）
- `GET /api/admin/refunds`（分页: memberName/status/orderNo）、`PUT /api/admin/refunds/{id}/approve`、`PUT /api/admin/refunds/{id}/reject` {reason}
- 原 `POST /api/admin/bookings/{id}/refund` 改为内部走同一 RefundService

## 8. 支付方式管理（V3, 个人中心绑卡）

- 敏感数据零落库：卡号/CVC 只进 Stripe；本地表 `member_payment_method` 仅缓存 brand/last4/有效期/默认标记；member 增 `stripe_customer_id`
- Stripe 通道：绑卡 = SetupIntent 流程。`POST /api/user/payment-methods/setup-intent` → {clientSecret}（首次自动创建 Customer）→ 前端 Stripe Payment Element(mode=setup) confirmSetup → `POST /api/user/payment-methods {stripePaymentMethodId}` 后端 PaymentMethod.retrieve 校验归属并缓存元数据
- Mock 通道：前端表单本地提取 brand/last4/有效期后仅提交这些字段（`POST /api/user/payment-methods {brand,last4,expMonth,expYear,holderName}`），全卡号不出浏览器
- 通用接口：`GET /api/user/payment-methods`、`PUT /{id}/default`（同会员互斥）、`DELETE /{id}`（Stripe 通道同时 PaymentMethod.detach）
- 支付页：已存卡列表可选 → `POST /api/payments/stripe/intent {orderNo, paymentMethodId?}` 用 customer+payment_method 直接确认；或"使用新支付方式"走原 Payment Element
- 用户端个人中心新增菜单「支付管理」/user/pay-methods

## 9. 多货币显示（V3, 展示换算 + 汇率管理）

- 语义：**展示货币仅影响显示，创建订单与扣款一律 CNY**（价格旁标注说明）。支持 CNY/USD/EUR/GBP/JPY
- 汇率源：open.er-api.com（公开免费无密钥，`GET https://open.er-api.com/v6/latest/CNY`）。后端 @Scheduled 每 6 小时刷新 + 启动时刷新一次；仅更新 `auto_update=1` 的行；API 失败保留旧值并记日志
- 管理员手工调整：`PUT /api/admin/exchange-rates/{code} {rate}` → source=2 且 auto_update=0（锁定不被自动覆盖）；`PUT /{code}/auto` 恢复自动；`POST /api/admin/exchange-rates/refresh` 立即抓取
- 公开接口：`GET /api/exchange-rates`（免登录）→ {base:'CNY', rates:[{code,name,symbol,rate,updateTime}]}
- 前端：navbar 货币下拉（地球图标旁，localStorage `user_currency` 默认 CNY）；useCurrency 组合式函数统一换算与格式化（JPY 取整无小数，其余两位；符号前置），应用于首页推荐/房间列表/详情/预约明细/支付页/我的订单等所有价格展示
- 管理端新增「汇率管理」页（系统管理组或独立菜单）：币种/符号/汇率/来源(API/手工)/自动更新状态/更新时间，行内改汇率、恢复自动、一键刷新
